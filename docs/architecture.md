# Unread architecture

## Boundaries

- React owns import/review/workspace state and device-only history in IndexedDB.
- `src/lib/parsers` handles text/JSON/WhatsApp imports. ZIP text expansion is bounded.
- `src/lib/privacy.ts` masks messages locally. The placeholder map never leaves the device.
- `src/lib/api.ts` lazily loads Supabase auth, sends prepared data, and handles cancellation. Only network failures receive one client retry; Gemini fallbacks belong to the server.
- `src/lib/validate.ts` validates model output against supplied message IDs before display. Citation membership is not proof of semantic correctness; users must still inspect cited source text.
- `supabase/functions/server/index.tsx` is intentionally only the Deno bootstrap.
- `app.ts` owns HTTP/CORS, identity verification, rate limiting, and safe error envelopes.
- `request.ts` bounds streamed request bytes and validates message/file shapes.
- `prompts.ts` builds instructions independently of untrusted, JSON-serialized chat data.
- `gemini.ts` owns provider transport with one 90-second total deadline and at most five model attempts. Model metadata is request-local. No upstream error bodies are logged or returned.
- `errors.ts` defines the shared backend error contract.
- `supabase/functions/_shared/languages.ts` is the single allowlist of the 28 supported languages; arbitrary language text cannot enter system instructions.

## Persistence and trust

Chat history and privacy maps are not written to Supabase. Gemini receives the submitted chat text or original screenshot/PDF content; masking cannot occur before vision transcription. Supabase persists only hashed rate-limit identities, window timestamps, and counters.

The Edge gateway should retain JWT verification. The application also verifies user tokens through Supabase Auth. The configured public anonymous key permits IP-based fallback for projects without anonymous sign-in; this depends on the gateway supplying trusted client-IP headers. Public keys are not user authentication. For a public production rollout, prefer verified users and gateway abuse protection; CORS is not authentication.

SQL rate limiting is atomic across isolates, fixed-window (30 requests per 10 minutes), and fails closed when unavailable. Fixed windows permit bursts across window boundaries. Hashed IPs are pseudonymous, not anonymous.

## Deploying this change

1. Apply `supabase/migrations/202610090001_unread_rate_limit.sql` to the connected project **before deploying the function**. The new function deliberately rejects AI requests if the RPC is missing. No migration was applied by this coding session.
2. Keep `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_ANON_KEY`, and `GEMINI_API_KEY` in server secrets only. Do not paste them into source or documentation.
3. Redeploy the server Edge Function through Make Settings. Ensure sibling modules and `_shared/languages.ts` are included.
4. Check `/make-server-82138c68/health` reports `version: unread-api-v2` and `gemini: true`. This checks code/config presence, not Gemini availability or the rate-limit migration.
5. Smoke-test analysis, Q&A, image/PDF transcription, malformed requests, and request protection using real user-provided content.
6. Schedule retention cleanup appropriate to traffic, for example deleting rate-limit rows older than one day. No scheduler is configured here.

The server entrypoint has repeatedly been replaced by an autogenerated starter. The cause remains unknown. Modularization limits the affected surface but does not prevent a future reset. Verify the bootstrap import and versioned health response before every sync/deployment.
